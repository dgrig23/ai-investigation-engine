## How AI was used

1. **Requirements analysis.** The Georgian task brief was translated and turned into a checklist; the
   AI proposed three project directions and the two-corpus design (HotpotQA for scale + measurable
   multi-hop retrieval, a synthetic incident corpus for the investigation scenario).
2. **Architecture.** The AI proposed the component split (ingestion / index / retrieval / llm / agent / api),
   Qdrant + local ONNX models, and an all-free LLM setup with provider fallback.
3. **Implementation.** First versions of all modules were generated by the AI and then run, tested
   and corrected. Bugs found during development (examples to keep in mind for the interview):
   - The document registry was first shared between chunking strategies, so indexing the second
     strategy would have marked every file "unchanged" and skipped it → registry made per strategy.
   - The contradiction detector first attributed every number in a chunk to the chunk's first incident
     id, so a weekly report listing two incidents produced a false conflict → facts are now attributed
     to the nearest preceding incident id on the same line (`contradictions._entity_at`), with a test.
   - Bulk dedup used a linear scan over seen ids (O(n²) on 74k docs) → replaced with a set.
4. **Evaluation.** Question set and metrics were drafted with AI; every expected answer was checked
   against the generator's ground truth.
