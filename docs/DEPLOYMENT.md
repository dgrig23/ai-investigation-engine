# Deployment (100% free tiers)

```
   browser ──HTTPS──► Render free web service (Docker, 512 MB RAM, sleeps after 15 min idle)
                         FastAPI + UI, bge-small ONNX model baked into the image
                         │                              │
                         │ HTTPS + API key              │ HTTPS + API keys (fallback chain)
                         ▼                              ▼
                 Qdrant Cloud free cluster          Groq → Cerebras → Gemini (free tiers)
                 (persistent: 67,752 chunks)
```

- **All state lives in Qdrant Cloud.** The container's disk is ephemeral; restarts and redeploys lose
  nothing except caches. Documents uploaded through the UI go to Qdrant and survive restarts.
- **Secrets** are Render environment variables entered in the Render dashboard, never in the
  repository (`.env` is git-ignored; `.env.example` has empty placeholders). Settings load them with
  `pydantic-settings` as `SecretStr`, so they never appear in logs.

## Why Render (and not Hugging Face Spaces)

The plan was Hugging Face Spaces (16 GB RAM free). At deploy time the API answered
`402 Payment Required - hosting Gradio and Docker Spaces on free cpu-basic requires a PRO subscription`;
only static Spaces are still free. Render's free web service builds the Dockerfile directly from
GitHub, but has **512 MB RAM and a fraction of a CPU**, which forced one measured trade-off:

| Production setting | Peak RAM (measured) | Warm search latency |
|---|---|---|
| bi-encoder + cross-encoder | ~650 MB (does not fit) | - |
| bi-encoder only (`USE_RERANKER=false`, `ONNX_THREADS=1`) | ~380 MB | ~0.5 s |

The cost of disabling the cross-encoder is measured in the evaluation (hybrid + MMR vs hybrid +
rerank + MMR). On a host with ≥ 1 GB RAM set `USE_RERANKER=true`.

## Steps

1. **Qdrant Cloud** - create a free cluster; copy its URL and an API key into `.env`.
2. **Index the data into the cloud from your machine** (embedding runs locally on CPU; HotpotQA
   embeddings are cached in `data/cache/`, the upload takes ~7 minutes):
   ```bash
   .venv/bin/python -m scripts.index_corpus --corpus incidents
   .venv/bin/python -m scripts.index_corpus --corpus incidents --strategy fixed
   .venv/bin/python -m scripts.index_corpus --corpus hotpotqa
   ```
3. **Render** - sign in with GitHub at render.com → **New → Blueprint** → select this repository.
   Render reads `render.yaml` (Docker runtime, free plan, Frankfurt, health check `/api/health`) and
   asks for the secret values: `QDRANT_URL`, `QDRANT_API_KEY`, `GROQ_API_KEY`, `CEREBRAS_API_KEY`,
   `GEMINI_API_KEY`. `ADMIN_TOKEN` is generated by Render.
4. Wait for the first build (~5-8 minutes), open the `.onrender.com` URL; `/api/health` must show
   `vector_db: ok (cloud)` and the configured LLM providers. Every push to `main` redeploys.

## Free-tier limits and how the app handles them

| Resource | Limit (free) | Handling |
|---|---|---|
| Render web service | 512 MB RAM, small CPU, sleeps after 15 min idle (cold start ≈ 1 min) | reranker off, 1 ONNX thread, models baked into the image, warm-up thread at startup |
| Qdrant Cloud | 1 GB RAM cluster; idle clusters can be suspended | int8 scalar quantization (vectors ~4× smaller in RAM), payload on disk; 67,752 chunks fit |
| Groq | per model: 1,000 requests/day, 8,000 tokens/minute | wait for short cooldowns (≤ 60 s), then fall back |
| Cerebras | 5 requests/minute, 1M tokens/day | second in the fallback chain |
| Gemini | slow / unreliable on the free tier during testing | last fallback |
| All LLMs exhausted | - | the app returns the retrieved evidence with status `llm_unavailable` |
| Public abuse | anyone can call the API | built-in corpora read-only without `ADMIN_TOKEN`; per-IP limit on questions; 10 MB uploads, supported formats only |

Cost: $0. At paid list prices the same design costs a few tenths of a cent per question
(1-4 LLM calls of ~2-3k input tokens; measured token counts are in the evaluation report).
